All data rates are width*height*bits/8*fps in decimal MB/s. They exclude
headers, padding, intermediate ISP formats, buffering and storage protocol
cost. Sensor rate is not necessarily file rate; no compression benefit assumed.
A fast SSD alone does not fix sensor receiver, ISP, buffer or USB bottlenecks.

Important website limitations:
- It labels 'full/crop' as firmware metadata, not proven sensor-area coverage.
- Listed fps are timing-table VMAX defaults, not fixed formats or guaranteed
  limits. Adjusting the UI estimate does not program the camera.
- Logical modes can reuse the same register payload with different timing.
- The FHD 29.97 selector uses representative M107 and says runtime mode ID is
  needed. Newer sensor-lab notes establish M106 for FHD29.97 CinemaDNG; local
  stock picker words at C0BE5888/C0BE5A28/C0BE5BC8 are all 106. Do not treat
  the site's representative camera-to-mode mapping as authoritative.
- RAW14 sensor entries do not establish a working RAW14 CinemaDNG recorder.
- The Sony/PDAF comparison explicitly does not prove fp has the necessary
  physical phase-detect mask. Finding dormant code does not unlock hardware.

Recommendation: extend one verified path at a time. Stabilize M117 and its
actual Bayer coverage/crop, then integrate gyro with effective geometry, then
research M130 or M56 depending on priority. Native menu descriptors and key
handling need separate reverse engineering; selecting a mode ID is not enough
without matching producer dimensions, stride, buffers, processing and recorder.
